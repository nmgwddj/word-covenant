# WordCovenant M1 macOS 真实采集人工验收清单

**目标：** 在真实 macOS 硬件上确认 WordCovenant 的 M1 本地采集链路能正确处理麦克风授权、输入设备变化、系统中断与队列压力，并且在整个过程中保持默认禁止出网。

**范围：** 本清单只验收真实麦克风采集的生命周期、时间线间隙与隐私约束。不验收 ASR、声纹区分、远程模型、网络工具或 Agent 执行。

**通过原则：** 任何硬件、权限或系统中断都必须以可见状态和/或本地间隙记录呈现；不得伪造连续时间线。未主动开启的出网能力必须保持关闭。

---

## M1、M2.1 与 M2.2 的验收边界

- 本清单中的场景 1 至 8 只构成 M1 的真实采集验收。它们不验收 ASR、VAD 或模型质量。
- M2.1 是纯 Rust、本地开发 mock 的管线合约：确定性 PCM/fixture 可以验证采集时钟、
  分段和 final 持久化，但不连接真实 CPAL ingress，且不代表真实 VAD 或
  `whisper.cpp`/Metal 已接入。M2.1 的离线测试不能替代本清单中的任何硬件证据。
- M2.2 已把真实采集连接到 M2.1 的本地管线：单一 dispatcher、`Starting -> Recording`
  的两阶段启动、16/48 kHz 预检及有界 job/result 队列均已在代码中实现。真实 macOS
  人工验收仍待执行；在同一构建的硬件记录完成前，M2.2 不能标记为人工验收通过。

## 前置条件

- [ ] 在一台有可用输入设备的 macOS 设备上执行，关闭其他会占用麦克风的应用。
- [ ] 使用当前待验收构建，确认应用版本和构建 SHA。
- [ ] 准备至少两个输入设备（例如内建麦克风与 USB/蓝牙麦克风）；若没有第二个设备，仍执行拔出/不可用场景并标记限制。
- [ ] 关闭 WordCovenant 的“允许出网”会话开关；退出并重新启动应用，确认其仍为关闭。
- [ ] 验收期间不安装模型、不导入远程资源、不配置 HTTP 工具，也不执行会访问网络的命令。
- [ ] 将应用日志、截图和可复现步骤保留在本机问题记录中，不上传音频、转写内容或网络观察数据。

## 固定记录字段

每个场景开始前和结束后记录以下字段；实际观察与预期不一致时，不得只填写“失败”。

| 字段 | 记录内容 |
| --- | --- |
| 执行人 / 日期 | 姓名或代号、当地日期与时区 |
| 机器型号 | 例如 MacBook Pro (M3 Pro) |
| macOS 版本 | 包含完整系统版本与架构 |
| 应用版本 | WordCovenant 版本、构建类型（debug/release） |
| 构建 SHA | 当前源码提交 SHA 或本机构建标识 |
| 输入设备 | 设备 UID、名称、采样率、声道数 |
| 场景时间 | 开始、关键操作、恢复、结束的本地时间 |
| 预期 / 实际 | 逐项填写可见状态、事件与时间线结果 |
| 结果 | 通过 / 失败 / 阻断 / 不适用 |
| 证据 | 本地截图、日志路径、会话 ID、gap/event ID |

## 场景 1：首次主动录音并允许麦克风权限

**步骤**

- [ ] 确认该应用此前未获麦克风权限；如环境不确定，使用附录中的 `tccutil` 命令重置后重启应用。
- [ ] 启动应用，但不要开始录音；确认未出现麦克风权限弹窗，状态为未录音。
- [ ] 主动点击开始录音。
- [ ] 在 macOS 权限弹窗中选择“允许”。
- [ ] 对着当前输入设备说话 10 至 20 秒，然后停止录音。

**预期**

- [ ] 权限只在用户主动开始录音后请求。
- [ ] 允许后状态按 `AwaitingPermission -> Recording` 进入录音，录音指示在实际采集前可见。
- [ ] 设备名称与实际选择的输入设备一致，音量指示对说话有响应。
- [ ] 停止后状态回到空闲，已采集区间的本地时间点保持有序。
- [ ] 未产生网络连接、出网授权、远程模型下载或 HTTP 工具调用。

**必须记录**

- [ ] 权限弹窗出现时间、用户选择、首次有电平时间、停止时间。
- [ ] 生命周期状态序列、会话 ID、输入设备 UID/名称和时间线截图。

## 场景 2：首次拒绝麦克风权限

**步骤**

- [ ] 在干净权限状态启动应用，主动点击开始录音。
- [ ] 在权限弹窗中选择“不允许”。
- [ ] 再次尝试开始录音，并关闭后重新启动应用再试一次。

**预期**

- [ ] 应用进入明确的非录音失败或恢复状态，不显示伪造电平或采集时间线。
- [ ] UI 说明权限被拒绝并给出前往系统设置恢复权限的路径；不反复弹出无法处理的权限请求。
- [ ] 重试和重启不会绕过 macOS 授权，也不会创建虚假的连续会话。
- [ ] 出网开关保持关闭，未产生网络行为。

**必须记录**

- [ ] 拒绝后的状态、错误提示、重试结果、重启后的结果和相关本地日志。

## 场景 3：在系统设置撤销权限后重新启动

**步骤**

- [ ] 先完成场景 1，使应用处于“已允许”状态，然后退出应用。
- [ ] 打开“系统设置 -> 隐私与安全性 -> 麦克风”，关闭 WordCovenant 的授权。
- [ ] 重新启动应用，主动开始录音。
- [ ] 重新允许或继续拒绝，并分别观察结果。

**预期**

- [ ] 应用不会把旧的允许状态当作当前权限。
- [ ] 重新启动后的第一次主动录音正确反映 macOS 当前授权状态。
- [ ] 撤销期间不采集、不保留假定连续的时钟区间；重新允许后只从新的真实采集点开始。
- [ ] 全程无出网。

**必须记录**

- [ ] 撤销时间、应用重启时间、重新请求结果、会话与 gap/event 记录。

## 场景 4：选择、切换与拔出输入设备

**步骤**

- [ ] 在未录音状态选择设备 A，开始录音并确认电平与设备名称。
- [ ] 停止后切换到设备 B，重新开始录音并确认电平与设备名称。
- [ ] 在设备 B 正在录音时拔出 USB 设备、关闭蓝牙设备或在系统中使其不可用。
- [ ] 设备不可用后等待状态稳定；重新连接或切回设备 A，并按 UI 提示恢复录音。

**预期**

- [ ] UI 和本地会话元数据记录实际设备 UID/名称，不把设备 A 的流标为设备 B。
- [ ] 未录音时的设备切换不产生采集数据。
- [ ] 录音中设备丢失进入 `Interrupted`、`Failed` 或明确的恢复状态，停止读取旧流。
- [ ] 设备丢失到恢复之间存在可见/可审计的 gap；恢复后的流使用新的时钟段，不复用旧采样偏移。
- [ ] 无设备时不可伪装成正在录音，且无出网行为。

**必须记录**

- [ ] 每次选择/切换/拔出的时间、设备 UID/名称、状态变化、gap 起止时间和恢复方式。

## 场景 5：系统睡眠与唤醒

**步骤**

- [ ] 使用有效输入设备开始录音并持续说话数秒。
- [ ] 让 Mac 进入睡眠，保持至少 30 秒后唤醒并登录。
- [ ] 观察应用状态和时间线，再按 UI 提示恢复或重新开始录音。

**预期**

- [ ] 睡眠期间不声称持续采集，也不把睡眠时长填充为音频时间线。
- [ ] 唤醒后捕获中断并显示可恢复状态或明确失败状态。
- [ ] 恢复成功时创建真实 gap 和新的时钟段；恢复失败时错误可见且可重新选择设备或重启会话。
- [ ] 未产生网络请求或自动恢复出网权限。

**必须记录**

- [ ] 睡眠、唤醒、状态改变、重新采集的时间及 gap/event 证据。

## 场景 6：队列压力与溢出

**步骤**

- [ ] 启动真实采集并使用开发构建的受控本地压力手段，或在本机制造足够长的 UI/消费者暂停，使有界 PCM 队列达到压力条件。
- [ ] 继续观察至少 60 秒，期间记录内存占用和应用响应性。
- [ ] 停止压力后继续采集，最后停止会话。

**预期**

- [ ] 实时回调不会因压力执行推理、磁盘写入、WebView 更新或阻塞等待。
- [ ] 队列容量始终有界；溢出时丢失区间被明确记录为 gap/overflow event，而不是伪造成连续采集。
- [ ] 应用保持可操作；恢复后时间线继续递增，不倒退、不重叠、不覆盖丢失区间。
- [ ] 内存不会随测试时长无限增长，且全程无出网。

**必须记录**

- [ ] 压力注入方式、起止时间、队列容量/溢出次数、gap 范围、峰值内存、恢复后的状态和日志。

## 场景 7：隐私出网总开关与零出网观察

**步骤**

- [ ] 新启动应用，确认“允许出网”开关默认关闭；退出并重启后再次确认。
- [ ] 在全部其他场景中保持该开关关闭，执行开始、停止、拒绝权限、设备切换、睡眠唤醒和队列压力操作。
- [ ] 查看应用本地审计/状态投影，确认没有出网授权启用、HTTP 工具运行、远程模型下载或网络错误重试记录。

**预期**

- [ ] 会话级出网总开关默认关闭且不会跨重启保持开启。
- [ ] 麦克风权限、采集生命周期、设备恢复和压力处理不依赖网络。
- [ ] 关闭状态优先于任何本地审批记录；本次验收中没有产生出网。

**必须记录**

- [ ] 每次启动时开关状态、审计中与出网相关的记录数量（应为零）、观察窗口和观察方式。

## M2.2 追加人工验收（代码已实现；真实 macOS 人工验收待执行）

本节验收真实 CPAL 采集到本地推理队列的桥接、时钟、背压和停止语义。它不验收真实
VAD、`whisper.cpp`/Metal、转写准确率、延迟或模型质量；M2.1 的 mock 测试也不能作为
本节的硬件证据。当前没有可执行本地 ASR 引擎时，正确结果是
`local_engine_unavailable` inference gap，而不是任何伪造文本。

M2.2 没有新增 HTTP 客户端、模型下载或连接开启路径。本应用只有在用户显式开启可见的
“允许出网”开关后，才可能按通用出网策略考虑后续请求；该开关仍不是充分条件，匹配的
审批也必需。本里程碑的全部验收保持开关关闭，预期为零出网。

### M2.2 前置条件

- [ ] 同一构建已完成本清单的 M1 场景，或每个未执行项有明确且可复测的阻断记录。
- [ ] 准备能实际报告为 16 kHz 和 48 kHz 的输入配置；记录设备 UID、声道数和实际
  采样率。若只有 44.1 kHz 等未支持配置，记录为阻断，不把它当作已验收的桥接输入。
- [ ] 构建提供仅本地、无 PCM/文本内容的诊断证据：两阶段启动顺序、唯一 dispatcher
  身份、会话/运行时 generation、ASR job/result 队列容量和当前深度，以及带采集范围的
  inference/transcript gap 或终态。
- [ ] 构建提供受控的本地压力/失败注入，能够分别使 job 队列和 result 队列达到满载；
  不使用网络服务、远程模型或上传的测试音频。
- [ ] 可在不配置可执行本地 ASR 引擎的条件下运行，并能观察到已形成 ASR request 的
  非内容计数或范围。
- [ ] “允许出网”开关关闭，并在应用重启后再次确认关闭；在应用进程上启动本地网络
  观察。测试语音、日志和证据都只保留在本机。

### 场景 M2.2-0：16/48 kHz 输入预检

**步骤**

- [ ] 以实际为 16 kHz 的输入配置开始、说话并停止一次；以实际为 48 kHz 的输入配置
  重复一次。
- [ ] 如可取得 44.1 kHz 或其他未支持配置，额外尝试开始一次，不能通过添加临时重采样
  或切换到 mock 绕过该检查。

**预期**

- [ ] 16 kHz 与 48 kHz 两次都能进入正常的桥接生命周期，记录的设备和采样率与系统
  实际配置一致。
- [ ] 未支持采样率在输入预检阶段明确失败，不创建伪造的录音会话、采集区间或转写。
- [ ] 本场景不以是否产生文本评价成功；没有可执行本地引擎时应进入后续
  `local_engine_unavailable` gap 检查。

**必须记录**

- [ ] 每次输入的设备 UID、名称、采样率、声道数、状态序列、会话 ID 与预检失败信息。

### 场景 M2.2-1：`Starting`/`Recording` 两阶段可见性与失败回收

**步骤**

- [ ] 使用本地诊断记录一次正常启动：准备权限/设备、parked dispatcher 与有界资源，交接
  CPAL 流，持久化 `Starting` 会话和启动审计束，arm 运行时，最后发布 `Recording`。
- [ ] 分别注入阶段一资源准备失败和阶段二 CPAL 启动/交接失败，再恢复为正常配置重复
  启动。

**预期**

- [ ] `Starting` 期间可在本地状态/诊断中辨识，但隐私状态和 WebView 都不得显示正在
  录音或暴露录音会话 ID。
- [ ] 只有 CPAL 已成功交接且 `arm_after_commit` 成功后，才进入并公布 `Recording`；提交
  前暂存的 PCM 必须丢弃，不能进入电平、ASR 或 gap 路径。
- [ ] 任一阶段失败都释放已创建的资源，留下可见的非录音失败/恢复状态；不会写入虚构的
  连续采集或转写区间。

**必须记录**

- [ ] 每次启动的阶段顺序、`Starting` 与 `Recording` 的时间、失败注入点、会话 ID、隐私
  状态投影、资源回收证据和后续正常启动结果。

### 场景 M2.2-2：唯一 dispatcher 与双路径分发

**步骤**

- [ ] 使用真实输入设备开始录音并持续说话，观察本地电平投影和 ASR job 路径的非内容
  计数/范围诊断。
- [ ] 在同一会话中停止并重新开始一次，确认每个会话的 dispatcher 生命周期独立。

**预期**

- [ ] `CaptureIngress` 只有一个原生读取者；电平与 ASR job 都由该 dispatcher 分发，
  不是两个竞争 `try_consume` 循环各自抢取 PCM。
- [ ] 电平路径保持紧凑且可响应，ASR job 的范围有序、不重叠；任何明确丢弃都能对应
  到可审计的范围结果，而不是被误报为连续转写。
- [ ] PCM 不出现在 WebView IPC、日志或人工验收材料中。

**必须记录**

- [ ] dispatcher 标识/生命周期、每条路径的计数或范围证据、会话切换点，以及任何
  inference/transcript gap 或终态的 ID。

### 场景 M2.2-3：job 与 result 队列背压

**步骤**

- [ ] 用本地受控方式暂停或减慢推理消费者，使 ASR job 队列达到满载；继续真实采集，
  再解除压力。
- [ ] 单独减慢 result 消费/持久化路径，使 result 队列达到满载；继续观察并恢复。
- [ ] 在两种压力期间和恢复后，记录内存、录音可停止性、队列容量/深度以及受影响的
  采集范围。

**预期**

- [ ] 两个队列都有固定上限；满载不会阻塞实时回调，不会让内存随测试时长无界增长，
  也不会使应用无法停止。
- [ ] job 满载产生带范围的 `job_queue_saturated` gap，result 满载产生带范围的
  `result_queue_saturated` gap；每条 gap 都有对应的本地审计事件，不能伪造为已经连续
  完成转写，也不能无声丢弃。
- [ ] 解除压力后，后续范围继续按采集时钟递增；final 结果不重复、不倒退、不覆盖原有
  审计修订。

**必须记录**

- [ ] 两个队列各自的压力注入方式、容量/峰值深度、满载开始和恢复时间、峰值内存、
  受影响范围、gap/终态 ID 及恢复后的审计验证结果。

### 场景 M2.2-4：缺少本地引擎的显式终态

**步骤**

- [ ] 以没有可执行本地 ASR 引擎的配置启动 16 kHz 或 48 kHz 输入，持续说话至本地
  诊断确认至少形成一个 ASR request，然后停止。

**预期**

- [ ] 每个已形成的 request 以 `worker/local_engine_unavailable` 的带范围 inference gap
  结束，并与 `InferenceGapRecorded` 审计事件一一绑定。
- [ ] 不产生 fixture、mock、partial 或 final 文本来冒充真实转写；PCM 也不进入 IPC、
  日志、SQLite 或人工验收材料。

**必须记录**

- [ ] 无引擎配置、request 数量/范围、每条 `local_engine_unavailable` gap ID、审计
  event ID 和会话停止结果。

### 场景 M2.2-5：停止 drain、重复退出与设备中断

**步骤**

- [ ] 在 job 或 result 仍有待处理范围时停止录音；另一次在待处理范围存在时使输入设备
  不可用或执行睡眠/唤醒场景。
- [ ] 在 drain 尚未完成时连续请求退出两次，观察应用是否仍等待 drain；随后重启并复查
  审计。
- [ ] 检查停止/中断后的本地状态、队列终止顺序、时间线和审计记录；重启应用后再次确认
  “允许出网”仍关闭。

**预期**

- [ ] CPAL 输入先停止，随后 dispatcher/推理工作者 drain；每个已接纳范围都在
  `CaptureInputStopped` 和 `SessionStopped` 前成为明确 final 或带范围 gap，不能悬挂、
  重复或伪造连续结果。
- [ ] 两个停止审计事件使用同一条连续采集时钟映射出的停止点；重复退出请求不能绕过
  drain，只有完成后才允许退出。
- [ ] 中断恢复不会复用旧采样偏移或把中断时间写入连续转写。

**必须记录**

- [ ] 停止/中断时间、队列深度、终止顺序、两个停止事件的采集时间/墙钟时间、所有未完成
  范围的最终状态和审计验证结果。

### 场景 M2.2-6：重启与 runtime generation 拒绝

**步骤**

- [ ] 让会话 A 留下一个可控的待交付 outcome，确认会话 B 在 A 完成 drain 前不能启动。
  A 正常停止后建立会话 B，再用开发构建注入会话 A 的旧 generation outcome。
- [ ] 检查会话 B 的时间线、gap/final、队列计数和审计记录，再重启应用复查。

**预期**

- [ ] 旧 generation 的 outcome 不能写入会话 B，也不能改变 B 的计数、转写或审计链；
  会话 A 的已接纳范围仍只在 A 中 drain 为 final/gap。
- [ ] 正常重启后出网开关恢复关闭，新的 runtime 使用新的 generation 和新的采集段，
  不复用旧时钟偏移。

**必须记录**

- [ ] 两个会话 ID、runtime generation、注入/释放时间、旧 outcome 的拒绝证据、两份
  时间线/审计验证结果和重启后的出网状态。

### 场景 M2.2-7：网络观察与默认零出网

**步骤**

- [ ] 在进程级本地网络监控持续运行时执行 M2.2-0 至 M2.2-6；全过程不打开“允许出网”。
- [ ] 退出并重启应用，再次确认开关关闭，并记录监控窗口、应用 PID 和观察方法。

**预期**

- [ ] 本里程碑不产生网络连接、模型下载、HTTP 工具调用或自动重试。任何未由用户显式
  开启开关触发的出网均为阻断。
- [ ] 可见开关是未来任何出网的必要条件，匹配审批仍是额外必要条件；M2.2 自身没有可
  以借此开关发起连接的实现。

**必须记录**

- [ ] 每次启动的开关状态、监控工具/窗口、PID、观察到的连接数（应为零）及与出网有关
  的本地审计记录数量（应为零）。

- [ ] 场景 1、2、3、4、5、6 中没有伪造录音状态、连续时间线或未记录的丢失区间。
- [ ] 所有设备丢失、睡眠和队列溢出均产生可追溯的状态或 gap/event 证据。

- [ ] 打包 `.app` 的用途描述存在且真实首次授权行为正确。

- [ ] 缺少本地引擎、背压、停止、设备中断和旧 generation 都产生定义明确的终态；没有

## M1 阻断条件

- [ ] 未主动开始录音即请求麦克风权限，或在未授权状态显示正在录音。
- [ ] 被拒绝、设备丢失、睡眠或队列溢出后仍伪造连续采集时间线。
- [ ] 录音/恢复过程自动打开出网开关、产生网络请求、下载模型或调用 HTTP 工具。
- [ ] 队列无界增长、应用长时间无响应、无法停止采集，或设备拔出后仍读取旧设备。
- [ ] 打包 `.app` 缺少 `NSMicrophoneUsageDescription` 或无法显示合法的授权弹窗。

## M2.2 阻断条件（仅在追加场景执行时适用）

- [ ] `Starting` 已被隐私状态/WebView 当作正在录音，或 `Recording` 在交接和 arm 成功前
  显示；提交前 PCM 被处理、计量或写成 gap 也同样阻断。
- [ ] 16 kHz 或 48 kHz 输入无法按记录配置启动，或未支持采样率被静默接受为正常会话。
- [ ] 存在第二个 `CaptureIngress` 消费循环，导致电平和 ASR 路径竞争同一 PCM packet。
- [ ] job 或 result 队列满载时阻塞实时回调、无界增长、无声丢弃，或缺少受影响采集范围的
  gap/终态证据。
- [ ] 无本地引擎时产生伪造文本，旧 generation 的 outcome 写入新会话，或停止/设备丢失/
  睡眠后留下不可终结的范围、重复 final、伪造连续转写。
- [ ] 在开关关闭时发生任何出网，或 M2.2 通过开关、审批以外的路径建立连接。

## 失败恢复与问题记录

1. 立即停止录音，关闭“允许出网”开关，并保留当前本地日志、会话 ID、截图与构建 SHA。
2. 不清理或修改原始证据；如需复测，创建新的会话并单独标记复测编号。
3. 记录最小复现步骤、预期/实际状态序列、输入设备 UID、时间范围、gap/event ID 和是否可稳定复现。
4. 若授权状态疑似被系统缓存，先退出应用，再由执行人主动使用附录的 `tccutil` 命令重置该应用的麦克风权限后复测。
5. 只有阻断问题修复并在相同构建或明确的新 SHA 上复测通过，才能标记相应的 M1 或
   M2.2 人工验收完成。

## 附录：仅本地构建与检查命令

以下命令只在本机工作目录、构建产物或本地系统权限数据库上操作；它们不访问网络。按需要在仓库根目录执行。

```sh
pnpm build
cargo fmt --manifest-path src-tauri/Cargo.toml --check
cargo test --manifest-path src-tauri/Cargo.toml
cargo check --manifest-path src-tauri/Cargo.toml --release
pnpm tauri build --debug --bundles app
```

检查打包后的用途描述。将下面的应用路径替换为实际构建产物路径：

```sh
plutil -extract NSMicrophoneUsageDescription raw -o - /absolute/path/to/WordCovenant.app/Contents/Info.plist
otool -L /absolute/path/to/WordCovenant.app/Contents/MacOS/WordCovenant
```

在需要复现“首次授权”时，可由执行人主动重置本机该应用的麦克风授权。此操作会清除 **本机** `com.wordcovenant.desktop` 的麦克风权限决定，随后必须重新启动应用；它不会删除会话数据。

```sh
tccutil reset Microphone com.wordcovenant.desktop
```
